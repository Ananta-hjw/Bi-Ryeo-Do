# 밸런스 기준과 검증

## 이번 조정의 범위

일반 후반의 긴 전투와 탑 보스의 급격한 난도 상승을 먼저 조정했다. 일반 전체를 억지로 일정 승률에 맞추거나 고난도 투자를 무의미하게 만들지는 않는다. 준비된 봇의 승률은 사람의 실제 승률과 다르다.

- 금요관: 모으기 공격이 실제 명중했을 때만 생명줄을 한 번 자른다. 연타도 공격 한 번으로 계산한다.
- 수화관: 살아 있는 각 멤버의 공격 참여를 확인한다. 같은 멤버의 반복 행동은 연계를 추가로 쌓지 않는다. 합공은 두 멤버가 참여하며, 방어·회복 등 지원 행동은 연계를 끊는다.
- 일반 24~30: 전투 대상 체력 x0.85, 공격 x1.25. 높은 체력으로 버티기를 요구하는 시험 전용 적(HpMul > 10)은 보존한다. 기존 방어·행동 스크립트·시험 제한·보상은 유지한다.
- 탑 5/15/25/30층: 보스와 호위의 공격을 각각 x0.8/x0.9/x0.95/x0.8로 보정한다. 일반층은 유지하고 30층 이후 보스는 x0.8 보정 위에 기존 층당 증가를 계속 적용한다.
- 어려움·극악, 의뢰의 적 수치는 이번 일반 전투 길이 조정에서 제외한다. `StageData.EnemyFor`를 전투·진형 계획·미리보기·시뮬레이션이 공유한다.

## 재현 가능한 빌드

`Assets/_Project/Tests/EditMode/BalanceSimulation.cs`가 공통 검증 도구다.

고정 레벨 비교는 실제 `StartKit`, 무료 기초 호흡법, 입문 숙련, 동료 무장비·훈련 없음·인연 0을 사용한다. 주인공과 동료는 동일 레벨이며, 자동 배치와 해당 이야기 단계의 봇 추천 무공을 사용한다. 일반 12부터 입장에 필요한 삼검룡을 가정한다. 소모품·합공·추가 장비·평판은 사용하지 않는다. 이 비교는 무공 구매 비용이나 전체 성장 경로를 증명하지 않는다.

별도의 1~6 연속 진행 테스트는 레벨1·두0으로 출발해 실제 보유 두로 무공을 구매하고 경험치·숙련·레벨업 회복을 적용한다. 소모품·추가 뽑기·선택 콘텐츠·재도전 없이 측정한다. 고정 레벨 비교와 결과를 혼동하지 않는다.

탑은 이야기 진행을 `max(8, min(30, 층+6))`으로 명시하고, 층 곡선의 권장 플레이어 레벨을 사용한다. 이는 통제된 비교 빌드이며 실제 모든 유저의 탑 도달 상태를 뜻하지 않는다.

## 동일 시드 전후 비교

후보 선택은 시드1~100, 최종 비교는 별도 시드301~600을 사용했다. 전후 비교 양쪽에 전투 규칙 수정을 적용하고 적 수치 보정만 다르게 했다. 승률은 전투 하나가 아닌 해당 스테이지/층 전체의 클리어율이다.

초반 연속 진행은 시드301~500의 200회 중 167회가 5스테이지를 통과했고, 그 167회 모두 6스테이지까지 통과했다. 첫 네 스테이지는 모두 통과했다. 초반의 고비를 없애거나 레벨6으로 6스테이지를 강제로 돌파하도록 조정하지 않았다. 실제 성장 경로에서는 6스테이지에 레벨7로 진입한다.

일반 중후반의 준비된 봇 승률은 여전히 높다. 이번 조정은 전투 길이와 막히는 구간을 다루는 첫 단계다. 다음 난도 상향은 실제 플레이의 판단 실수·동료 성장 격차·장비 확보 비용을 측정한 뒤 판단한다. 극악 후반·상위 승급의 완성 빌드와 Unity 조작감은 이번 검증으로 보장하지 않는다.

## 회귀 검증과 다음 조정

외부 .NET 8 프로젝트 구성은 `CLAUDE.md`를 따른다.

```bash
dotnet test <Core와 EditMode 소스를 포함한 프로젝트.csproj>
dotnet test <프로젝트.csproj> --filter FullyQualifiedName~BalanceTests
```

- 일반 권장 레벨: 40회 중 34회 이상, 5스테이지는 28회 이상 통과한다.
- 초반 연속 진행: 200회 중 130~190회가 5스테이지를 통과하고, 그중 90% 이상이 6스테이지를 통과한다.
- 조정한 탑 보스: 고정 빌드 100회 승률60~95%. 한 레벨 성장했을 때 승률이 낮아지지 않아야 한다.
- 일반 후반: 높은 클리어율을 유지하면서 스테이지별 행동 수 상하한으로 지나친 장기전과 전투 생략을 검출한다.
- 필수 삼검룡 승급: 신진은 안전한 선택지, 고수는 위험과 보상이 있는 선택지로 검증한다. 실제 `TurnLimitFor`를 사용한다.

승률은 임계점 근처에서 급변한다. 예를 들어 탑20층은 공격 +5%에서 약88%였지만 +7.5%에서 0%가 됐다. 후보는 작은 간격으로 비교하고 다른 시드 및 성장 전후 빌드로 검증한다. 위 범위는 현재 통제 빌드의 회귀 기준이며 모든 플레이어에게 적용할 절대 목표가 아니다. 수치 변경 시 이 문서의 조건과 전후 결과도 갱신한다.

## 상태 이상 도입 후 보정

상태 이상(`Docs/GAME_DESIGN.md`「상태 이상」)을 넣자 혼자 싸우는 5스테이지의 염도 곽영희(모든 기술이 화상)가 초반 연속 진행 기준을 벗어났다(시드301~500 중 5스테이지 통과 167 → 97, 권장 레벨 40회 중 22회). 이 전투는 임계점에 붙어 있어 화상 수치(8% → 4%)나 확률을 낮춰도 거의 회복되지 않았고(97~112), 공격 보정은 x0.86에서야 움직였다. 화상 규칙은 그대로 두고 염도의 체력만 줄여 싸움을 짧게 했다. 상태 이상을 한 번에 하나만 걸리게(걸린 동안 다른 것·연장 없음) 바꾼 뒤 다시 재서 `HpMul` 2.666 → 2.5(약 -6%)로 정했다(2.55는 129/200으로 기준 아래, 임계점이 2.5~2.55 사이). 결과는 5스테이지 통과 181/200, 6스테이지 모두 통과이며 `BalanceTests`와 권장 레벨 테스트(28/40 이상)를 모두 통과한다. 어려움·극악의 염도도 같은 배율에서 출발하므로 체력이 같은 비율로 줄었다.

## 보스 단계 전환 도입 후 보정

보스 단계 전환(`Docs/GAME_DESIGN.md`「보스 단계 전환」)을 넣자 5스테이지가 다시 흔들렸다. 게이지 초기화 없이 기술 순서만 바꾸면 권장 레벨 17~24/40(염도 체력 2.2~2.5에서 모두 기준 아래, 체력으로는 회복되지 않음), 바뀔 때 보스 게이지를 0으로 하면 40/40·200/200으로 기준(130~190) 위였다(게이지 절반 깎기는 순서만 바꾼 것과 같았다). 게이지 초기화를 두고 염도 `HpMul`을 올려 맞췄다: 3.3 → 37/40·200/200, 3.4 → 28/40·200/200, **3.45 → 30/40·152/200**, 3.5 → 28/40·152/200, 3.6 → 28/40·149/200. 3.45로 정했다(원래 2.666보다 약 +29%). 나머지 일반 스테이지는 권장 레벨 40회 중 1스테이지 37, 나머지 40이다.

이어서 단계마다 공격력·방어력을 올렸다(50% 공격 +10%, 25% 공격 +30%·방어 +20%). 1스테이지 백호가 권장 레벨 30/40(기준 34), 5스테이지 염도가 26/40으로 내려갔다. 백호는 `HpMul` 1.822 → 1.75로 36/40(캠페인 200/200)이 됐다. 염도는 체력만으로는 권장 레벨과 캠페인을 함께 맞출 수 없었다(체력 3.25 → 28/40·200/200, 3.5 → 20/40·147/200, 3.7 → 20/40·102/200). 그래서 1단계의 공격 상승만큼 기본 공격을 낮췄다: 3.5/1.35 → 27/40·178, 3.6/1.35 → 29/40·170, 3.7/1.30 → 37/40·182, **3.65/1.32 → 35/40·171/200**으로 정했다(`HpMul` 3.65, `AtkMul` 1.458 → 1.32). 다른 일반 스테이지는 모두 40/40이다.

## 일반 난이도 적 체력 상향 (`StageStars.NormalHpBoost`)

일반 난이도의 적이 무공 한두 번에 쓰러진다는 지적에 따라 일반 난이도 적에게 체력 배율을 곱한다(어려움·극악은 표에서 출발하므로 영향 없음, 의뢰·무한 비무대·승급 비무·시험 전용 적(`HpMul` > 10)도 제외). 스테이지 1·6은 x1.0, 2~5는 x1.1(혼자 싸우는 구간이라 봇 벼랑 끝), 7은 x1.45에서 스테이지마다 +0.05씩 올라 30에서 x2.6이다. 공격은 7스테이지부터 x1.05에서 스테이지마다 +0.005다. 24~30스테이지의 기존 x0.85 체력·x1.25 공격 조정은 그 위에 그대로 곱한다.

균형 봇은 장비·심법·숙련·아이템을 쓰지 않아 한계 직전에서 약 90%를 이기도록 맞춰 둔 상태였으므로, 체력을 올리면 추천 레벨에서 못 깨는 스테이지가 생긴다(사용자 결정: 봇 기준을 완화). 그래서 7스테이지 이후의 봇은 `BalanceSimulation.EdgeLevels(stage)` = (stage - 4) / 3(정수 나눗셈, 7에서 +1, 30에서 +8)만큼 추천 레벨보다 높게 싸운다(`BalanceSimulation.BotLevel`; 실제 플레이어가 장비 등으로 봇보다 강한 만큼을 뜻한다). 필요한 추가 레벨은 스테이지 29(시험)가 +8, 27이 +5이고 나머지는 대부분 0~3이다. 1~6스테이지(시작 꾸러미만 쓰는 구간)는 추가 레벨이 없다.

결과: 추천 레벨(+추가 레벨)에서 40판 중 34번 이상을 모든 스테이지가 만족하고(스테이지 1은 36/40, 5는 35/40), 초반 연속 진행 기준은 5스테이지 171/200(130~190), 6스테이지 171/171이다. 24~30스테이지의 평균 행동 수 범위는 길어진 전투에 맞춰 올렸다(24: 90~145, 25: 75~122, 26: 75~123, 27: 85~131, 28: 105~165, 29: 160~256, 30: 100~158; 측정 115·97·98·105·132·205·126). 신속 별 한도 표(`StageStars.FastLimits`)는 새 적과 봇 레벨로 다시 쟀고(전투별 중앙값의 90%+1), 어려움·극악의 한도는 일반의 체력 상향만큼 나눠서 이어받는다.

## 보스 단계 전환: 게이지 초기화 제거 후 보정

단계가 바뀌면 보스의 행동 게이지를 0으로 돌려 한 차례를 잃게 했더니, 비류연 → 보스 → 비류연 순서에서 비류연이 때려 단계가 바뀌면 보스의 차례가 사라지고 비류연이 연달아 움직였다. 게이지 초기화를 없애 보스가 그대로 차례를 가진다(`BossPhaseTests.ThePhaseChangeDoesNotCostTheBossItsTurn`). 그러자 5스테이지의 염도가 어려워져(추천 레벨 16/40, 캠페인 73/200) 체력과 공격을 함께 낮춰 맞췄다: 3.65/1.2 → 17/40·77, 3.3/1.1 → 26/40·157, **3.3/1.0 → 32/40·171/200**(`HpMul` 3.65 → 3.3, `AtkMul` 1.32 → 1.0), 3.0/1.0 → 34/40·178. 다른 스테이지는 그대로다.
