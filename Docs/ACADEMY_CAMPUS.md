# 천무학관 탐색 첫 버전

강호 → 도전 → 천무학관에서 마당을 연다. 기존 `Academy.Unlocked` 해금 조건을 따른다.

## 조작과 기능

- 모바일: 왼쪽 조이스틱으로 이동하고, 시설 입구에서 오른쪽 입장 버튼을 누른다.
- PC: WASD·방향키로 이동하고 E키로 입장한다.
- 시설: 수강신청·수업, 동호회, 단 대항전. 기존 과목 선택·보상·전투 준비 흐름을 사용한다.
- 시설 화면의 뒤로 가기는 마당, 마당의 뒤로 가기는 강호로 돌아간다. 전투 이후에도 마당으로 복귀한다.
- 마당 위치는 AcademyPanel이 살아 있는 동안 유지된다. 앱 재시작 후에는 중앙 아래에서 시작한다. 저장 형식 변경은 없다.
- 카메라는 플레이어를 따라가되 지도 경계에서 멈춘다. 건물과 화단은 발 위치와 반경을 기준으로 통과할 수 없다.

## 구현과 아트 범위

`AcademyWalk`는 Unity 독립 이동·충돌·시설 접근 판정, `AcademyCampus`는 캔버스 기반 지도와 카메라, `AcademyJoystick`은 단일 포인터 소유와 해제 처리를 담당한다.

마당은 돌길·잔디·낮은 화단 배경과 세 시설의 별도 외관 아트를 사용한다. 원작 학관의 정확한 지형도가 아니라 기존 동선을 시각화한 게임용 배치다. 수강·동호회 소재는 Story/analysis/vol03.md를 참고하며 새 사건·대사·인물은 추가하지 않는다. 탐색 전용 `Resources/Art/Exploration/player_walk.png`의 4방향 대기·걷기 그림을 사용한다. 시트가 없거나 읽을 수 없으면 `player.png` 기본 대기로 대체한다. 전투 SD는 `Art/Battle/`에 별도로 유지한다.

마당 지형과 시설 외관을 적용했다. 걷기 시트는 첫 애니메이션 초안이며 실제 화면 크기에서 보폭·옷 움직임의 연결감을 확인한 후 다듬는다. 기존 전투 SD 경로를 덮어쓰지 않는다.

## 검증

.NET에서 AcademyWalkTests와 기존 AcademyTests 12개 통과. 이동 속도·대각 정규화·경계·화단과 건물 충돌·시설 접근·잘못된 입력을 검사했다.

전체 Core 회귀 실행: 1,602개 통과, 136개 실패, 명시적 테스트 1개 미실행. 이전 136개 실패와 이름 집합이 같으며 새 실패는 없다.

AcademyJoystickTests는 Unity Editor용이며 이 클라우드에서는 실행하지 못했다. Unity Play 모드와 Android에서 아래를 확인해야 한다.

1. 학관 해금 전 안내, 해금 후 마당 진입, 16:9·20:9·4:3 안전 영역과 조이스틱·입장 버튼 표시.
2. 이동·카메라 추적·지도 경계·화단 우회·건물 충돌, 조이스틱 바깥 드래그·멀티터치·손 떼기·앱 일시 중지.
3. 세 시설 진입, 과목 선택·가입 후 화면 유지, 시설→마당→강호 뒤로 가기와 Android 뒤로 키.
4. 수업·단 대항전 준비 취소 및 전투 종료 후 위치 유지와 기존 보상 처리.
5. 도움말 표시 중 키보드 이동 차단, 마당 재진입 시 조이스틱 입력 초기화.

실제 렌더링·터치·Unity 컴파일 검증은 별도 필요하다. .NET 결과로 대체하지 않는다.

## 4방향 걷기 연결

- `player_walk.png`: 투명 PNG 시트, 위에서부터 아래·왼쪽·오른쪽·위 방향. 각 행은 대기·왼발·통과·오른발 포즈의 네 칸이다.
- `player_walk_atlas.json`: 원본 해상도와 프레임 16개의 픽셀 영역. 생성 시트의 실제 인물 범위를 측정해 런타임에 분리한다. 원본 이미지는 자르거나 덮어쓰지 않는다.
- `ExplorationSprites`: 읽기 가능한 텍스처 설정 없이 Sprite.Create로 프레임을 만들고 재사용한다. 임포트 해상도나 메타데이터가 다르면 기본 대기로 복귀한다.
- `ExplorationMotion`: 실제 이동량으로 방향을 정하고 초당 8프레임으로 1→2→3→2를 반복한다. 대각 이동은 큰 축, 동률은 세로 방향을 사용한다.
- 정지·충돌·도움말 표시 때 마지막 방향의 대기로 돌아간다. 방향 전환 시 첫 걷기 포즈부터 시작한다.
- 프레임은 공통 픽셀 배율과 하단 피벗으로 표시해 발 위치와 크기 변동을 줄인다. 좌우 방향별 아트를 사용하므로 더 이상 통째로 반전하지 않는다.
- Unity에서 `ExplorationSpritesTests`를 실행하고 네 방향의 보폭·발 높이·구역 재진입·도움말·벽에 막힌 상태를 확인해야 한다. 이 클라우드에서 실제 Unity 렌더링은 미검증이다.

걷기 추가 후 검증: 관련 Core 테스트 19개 통과. 전체 Core는 1,609개 통과·136개 실패·명시적 테스트 1개 미실행이며, 이전 실행과 실패 테스트 이름 집합이 같다. 시트 16개 프레임의 투명도·원본 크기·영역 범위도 검사했다. Unity용 ExplorationSpritesTests와 실제 화면 검증은 미실행이다.

## 마당 배경과 시설 외관

`Resources/Art/Exploration/Academy/`에 배경과 외관을 분리했다.

| 파일 | 사용 |
|---|---|
| `courtyard.png` | 2400×1600 지도에 맞춘 돌길·잔디·화단 배경, 원본 1536×1024 |
| `facilities.png` | 수강·수업 건물, 동호회 건물, 단 대항전 건물의 투명 시트, 원본 2172×724 |
| `facilities_atlas.json` | 세 건물의 원본 픽셀 영역, 왼쪽부터 기능 순서 |

`AcademyScenery`는 배경과 외관을 읽고 시설 스프라이트를 재사용한다. PNG는 읽기 비활성·밉맵 비활성·NPOT 크기 유지·압축 비활성·최대 4096 설정이다. 시설 시트 좌표를 유지하려면 자동 축소하지 않아야 한다.

시설은 기존 충돌 영역(x 중심 ±200, y1150~1450)에 맞춰 표시한다. 이름표는 건물 위, 입구 표시는 기존 접근 위치 앞에 둔다. 건축·색·장식은 미술적 해석이며 새 사건·NPC·대사·보상은 추가하지 않는다.

배경 로드 실패 시 기존 도형 지형으로, 시설 로드 실패 시 기존 건물 블록으로 대체한다. 이동·카메라·충돌·시설 해금·진입 로직은 변경하지 않았다.

원본 크기·투명도·3개 분리 영역·임포트 설정 및 diff 공백 검사를 통과했다. `AcademySceneryTests`는 Unity용 임포트 검사이며 실행하지 못했다. 이번 변경은 아트와 표시 계층이며 Core 테스트는 재실행하지 않았다.

Unity에서 기존 학관 확인 항목에 더해 배경과 화단 충돌의 일치, 세 시설의 외관·이름표·입구, 카메라 이동 중 잘림, 16:9·20:9·4:3 화면, 대기·걷기 중 시설 앞뒤의 겹침을 확인한다. 실제 게임 캡처나 렌더링 검증 결과로 생성 이미지를 사용하지 않는다.
