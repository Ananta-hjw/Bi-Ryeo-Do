# UI 가독성 기준과 점검 범위

## 공통 기준

- 기준 너비는 1080이며 화면 너비에 맞춰 배율을 정한다. 세로로 긴 기기에서 글자가 상대적으로 작아지지 않도록 `CanvasScaler.matchWidthOrHeight`는 0을 사용한다.
- 스토리 본문은 42, 설명창은 36, 목록 보조 글은 주로 30, 상태창은 32 이상을 사용한다. 주요 탭은 36, 버튼은 최소 30이다. 단위는 기준 캔버스 픽셀이다.
- 긴 설명과 목록은 자동 축소를 끈다. 일반 라벨의 축소 하한은 28이며, 그보다 작은 크기를 명시한 전투의 밀집 표시·장식은 별도로 유지한다.
- 본문은 고딕 보통체와 1.15~1.35 줄 간격, 좌측 정렬을 사용한다. 한글 서술에 기울임꼴을 쓰지 않는다. 제목의 명조 서체와 무협 색상은 유지한다.
- 비활성·완료 상태도 읽을 수 있도록 밝은 회색을 사용한다. 상태를 색만으로 전달하지 않고 글자도 표시한다.

## 구현

`UiFactory.ScrollBody` / `ReadingText`는 고정 글자 크기를 유지하며 실제 글꼴의 높이를 측정한다. 본문이 길면 세로로 읽을 수 있고, 내용이 바뀌면 맨 위로 돌아간다. 본문 폭·글꼴·내용 변경을 반영하며 읽기 위치를 매 프레임 초기화하지 않는다. 긴 영역에는 스크롤 표시가 나타난다.

`ReadingList`는 행 안의 글을 측정해 필요한 만큼 행 높이를 늘리고, 그 아래 행과 전체 목록 높이를 다시 배치한다. 행이 숨겨졌다가 나타나는 필터·뽑기 결과도 갱신한다. 텍스트 변경·행 활성 상태·폭 변경 시 재측정하며, 매 프레임 전체 글꼴 측정을 반복하지 않는다. 큰 대체 그림 글자는 높이 계산에서 제외한다.

스토리는 `UiFactory.Pages`가 실제 글꼴과 대화 영역으로 측정하고 `ReadingPages`가 문장 끝·공백에 가까운 곳에서 나눈다. 원문의 글자·공백·탭·줄바꿈을 삭제하지 않으며 UTF-16 보조 문자를 둘로 자르지 않는다. 한 번 누르면 현재 쪽의 글이 모두 나오고, 다시 누르면 다음 쪽으로 넘어간다. 화자와 진행도는 계속 보인다.

새 목록 행은 `ReadingList.Register(row, minimumHeight, gap)`로 등록한다. 스크롤 본문의 위치를 바꿀 때는 텍스트 자체 대신 `UiFactory.ReadingViewport(text)`를 사용한다. 원문이나 Core의 게임 규칙을 바꿔 화면에 맞추지 않는다.

## 화면별 반영

| 범위 | 변경 |
|---|---|
| 공통 라벨·버튼·하단 탭 | 과도한 자동 축소 제한, 대비 개선, 버튼·탭 글자 확대, 탭 영역 확대 |
| 도움말·경지 알림 | 읽기 영역 확대, 고정 본문·스크롤, 본문과 확인 버튼 분리 |
| 스토리·추억·전투 중 보스 대사 | 큰 고정 본문, 페이지 분할, 진행도, 서술 기울임 제거 |
| 전투 결과·정비·길게 누르기 설명 | 넓은 스크롤 본문, 독립된 닫기 버튼, 설명 안에서 읽을 때 닫힘 방지 |
| 상태창 | 글 길이에 따른 행 높이, 능력치 값과 보너스 구분, 동료 능력치 줄바꿈, 세트·장비·심법 설명의 공간 확보 |
| 행낭·무공 | 행낭은 3열 카드(이름·착용 여부·효과·세트), 장비 관리 버튼은 상세창으로 이동. 무공은 내용에 맞는 행 높이, 긴 상세·알림 스크롤 |
| 동료 장비 선택·수련서 선택 | 스크롤 목록으로 표시해 하단 버튼과 겹침 방지 |
| 뽑기 | 좁은 2열 결과를 넓은 1열 스크롤 목록으로 변경, 긴 이름·효과 설명 표시 |
| 도감·업적·동료 수련·심법 | 내용에 맞춰 늘어나는 목록 행과 큰 보조 글자 |
| 임무·별 보상·세력·객잔·전승의식 | 보상·설명·안내의 글자 확대, 긴 안내 스크롤, 목록 행 측정 |
| 강호·스테이지·출전 준비·의뢰·승급·기연 | 목록 행 자동 조절, 준비창의 긴 적 목록과 안내 스크롤, 진형 안내 정리 |
| 설정·도움말 목록 | 전체 도움말을 스크롤 목록으로 표시, 화면 아래로 벗어나던 항목 수정 |
| 기록·이야기 목록·추억 목록 | 큰 요약·보조 글자, 긴 제목에 맞춘 행 높이 |
| 로비 대화·요약 | 넘치는 글 스크롤, 긴 대화의 자동 교체 대기 시간 확대 |
| 전투 HUD·인물 칸 | 명령 보조 글자 확대, 긴 무공명 두 줄 영역 확보, 체력 수치 우선 표시 |

전투 인물 칸의 내공·기세는 작은 숫자 대신 막대로 표시한다. 정확한 값은 현재 인물 HUD와 인물 상세창에 표시한다. 적의 개별 칸은 공격·저격·전조·강타 대상처럼 짧게 요약하고, 기술 이름은 상단 적 정보 띠와 적 상세창에서 읽는다.

## 검증

전체 Core/Game 소스는 Unity API 참조 어셈블리로 컴파일한다. `Assets/_Project/Tests/UI/ReadingPagesTests.cs`는 빈 글, 긴 한글·명시적 줄바꿈·탭, 보조 문자 경계, 작은 영역, 문장 분할과 기존 이야기 데이터의 원문 보존을 검사한다. 순수 C# 페이지 분할 테스트 7개를 .NET/NUnit으로 실행했다.

Unity가 없는 환경의 컴파일과 문자열 테스트는 실제 폰트 렌더링·스크롤·입력을 대신하지 않는다. Unity 2022.3.62f1의 Test Runner에서 `BiRyeoDo.Tests.UI`를 실행하고 다음을 Play 모드와 Android에서 확인한다.

1. 9:16과 9:19.5 안전 영역에서 탭·닫기·확인 버튼과 본문이 겹치지 않는지 확인한다.
2. 가장 긴 도움말·무공·세트 설명과 큰 체력·재화 수치에서 글이 축소되거나 잘리지 않는지 확인한다.
3. 이야기에서 첫 누름의 글 전체 표시, 다음 누름의 쪽 이동, 마지막 쪽·건너뛰기·빠른 연속 누름을 확인한다.
4. 모든 상태창 구역과 긴 동료 장비명을 끝까지 읽을 수 있는지 확인한다.
5. 행낭 필터를 번갈아 누르고 뽑기 결과를 연속 표시할 때 행이 겹치지 않는지 확인한다.
6. 도움말의 마지막 항목, 동료 장비 선택의 마지막 인물, 출전 준비의 마지막 적까지 접근되는지 확인한다.
7. 설명을 스크롤할 때 창이 닫히지 않고, 닫기·뒤로·확인·아이템 사용·습득·장착·분해의 기존 동작이 유지되는지 확인한다.
8. 전투에서 사거리 밖·강타 대상·상태 이상·필살기 부족·긴 무공명과 전체 수치 상세창을 확인한다.

## 안내창 잘림 및 행낭 개편

스크롤 본문의 높이를 갱신할 때 `sizeDelta.x`가 0으로 초기화되어 음수 가로 위치와 함께 왼쪽 글자가 마스크에 잘렸다. 본문은 왼쪽 16, 오른쪽 42의 여백을 유지하며 같은 폭으로 줄바꿈 높이를 측정한다. `ReadingViewportTests`는 짧은 글·긴 글·짧은 글로 갱신하면서 양쪽 경계와 맨 위 복귀를 검사하는 Unity Editor 회귀 테스트다. 클라우드에는 Unity 실행 환경이 없어 이 테스트의 실행과 실제 화면 확인은 별도로 필요하다.

행낭은 한 줄에 3개씩 배치하고 같은 줄에서 가장 긴 이름·효과에 맞춰 카드 높이를 정한다. 장비의 서술·강화·분해 정보는 상세창에만 표시한다. 장착·해제·강화·분해도 상세창에서 실행하며, 목록의 일괄 분해 버튼은 제거했다. 장비 내부의 전체 필터를 제거하고 무기·상의·하의·신발·장신구만 표시한다. 보유 종류가 60개를 넘어도 카드가 추가된다. 소모품 사용·재료 합성·판매는 해당 아이템 상세창에서 실행한다.
